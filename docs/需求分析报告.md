# 金属增材制造自动化工厂需求分析报告

## 1 引言

### 1.1 编写目的

需求分析报告能够详细、准确地反映最终确定的自动化工厂的需求内容，并能够简要地反映需求分析的过程以及相关问题。它既是对需求分析的工作总结，又是后续阶段的工作纲领。

本报告面向项目开发团队、指导教师及验收专家，旨在：

1. 明确 AGV 小车系统在金属增材制造工业 4.0 场景下的功能边界与性能指标；
2. 将用户需求转化为可验证的技术需求，为后续设计说明书、程序流程图及测试计划提供依据；
3. 记录需求分析过程中的关键决策与权衡取舍，确保需求可追溯；
4. 为各功能模块的详细设计提供输入约束，包括硬件资源分配、时序要求、接口协议等。

### 1.2 项目背景

随着 AGV 小车的广泛应用，市场对 AGV 产品的适应能力、功能要求、定位精度、承载能力等提出了越来越高的要求，AGV 小车功能呈现多用性发展趋势。AGV 小车集光、电、机、计算机为一体，综合了当今科技领域先进的理论和技术，可以快捷地与各类生产线、装配线等有机结合，可以根据不同的需求，以不同的组合，进而实现各种不同的功能，具有突出的兼容性及良好的适应性。

近年来，金属增材制造行业发展迅速。在增材制造的工业 4.0 中，AGV 小车带来了新的机遇。通过引入 AGV 小车来完成繁琐枯燥的送粉工作，实现金属增材制造的自动化生产，可以显著降低安全风险，促进生产效率。

本项目即在此背景下，设计一套基于 STM32 嵌入式平台的 AGV 小车控制系统，实现沿黑线路径自主循迹行驶、超声波障碍物检测与避让超车、K210 视觉识别路牌指令响应等功能，模拟金属增材制造工厂中 AGV 向 3D 打印机运送粉末的全流程。

## 2 概述

### 2.1 产品描述

1. AGV 小车主要用于实现沿指定的黑线路径自主行进，将金属粉末运送至 3D 打印机前（以挥手遮挡/超声波检测障碍物模拟）；
2. AGV 小车应能识别路径上的障碍物（3D 打印机或其他 AGV），自动执行超车避让机动，绕过障碍物后恢复循迹行驶；
3. AGV 小车应能识别 K210 视觉模块发送的路牌指令（左转、右转、鸣笛、减速、加速、红/黄/绿灯、倒车等），做出相应的驾驶响应；
4. AGV 小车的标牌标志、电子部件的标志以及导线标志应清晰、美观、正确、完整；
5. AGV 小车的安全性应符合国家相关标准，不得存在安全隐患；
6. AGV 小车应具备自检测、自诊断、自保护功能，包括电源故障、电机驱动器故障、电池电压过低、路径导引失败、无线通讯中断等；
7. AGV 小车应具备声光报警功能，发生故障时能及时通知监控系统，出现断电和其它意外故障时，系统应有安全的处理措施；
8. AGV 小车应具备 OLED 实时状态显示功能，便于调试和运行监控。

## 3 具体需求

### 3.1 内部功能需求

#### 3.1.1 沿指定路径运送金属粉末（FR-01）

**功能概述**：AGV 小车通过四路红外对管传感器检测地面黑线位置，采用比率差速弧线转弯算法实现平滑循迹行驶，将金属粉末沿指定路径运送至 3D 打印机。

**详细需求**：

1. **行进速度**：9～45 m/min，速度可调（PWM 占空比控制，速度参数范围 2100～3599，对应 ARR=3599 的 20 kHz PWM 有效占空比区间）；

2. **定位精度**：±20 mm（循迹偏差通过四路红外传感器加权位置计算，弧线差速修正）；

3. **导航方式**：红外循迹，4 路红外对管传感器（物理排列从左到右：X2→X1→X3→X4，对应 PF14→PF13→PF15→PG0），电平约定：黑线=低电平(0)，白地=高电平(1)；

4. **爬坡能力**：3%（70%负载）；

5. **通讯方式**：USART2 串口通讯（PD5 TX / PD6 RX，AFIO 重映射，因 PA3 物理损坏），115200 8N1，`$payload#` 帧协议；

6. **行走姿态**：可实现 AGV 小车的前进、后退、左转、右转、差速弧线转弯、原地旋转、停止；

7. **循迹控制算法**：比率差速弧线转弯（详见 3.1.1.1）。

##### 3.1.1.1 循迹控制算法详述

**位置计算**：四路传感器加权平均，权重从左到右为 −3/−1/+1/+3：

```
position = Σ(weight_i × sensor_i) / Σ(sensor_i)    （仅统计检测到黑线的传感器）
```

当所有传感器均未检测到黑线时（全白），维持上次误差值。

**比率差速弧线转弯**：不使用固定 Kp，而是通过 `outer_forward`（外侧轮前进速度）和 `turn_ratio`（0~100）计算内侧轮反转速度：

```
inner_reverse = outer_forward × turn_ratio / 100
```

| ratio 值 | 含义 | 内侧轮行为 |
|----------|------|-----------|
| 0 | 纯直行 | 内侧轮同速前进 |
| 50 | 温和弧线 | 内侧轮以 50% 速度反转 |
| 100 | 原地旋转 | 内侧轮全速反转=原地旋转 |

**四档 ratio 配置**（应对不同误差等级）：

| 档位 | 场景 | outer_forward | turn_ratio | inner_reverse (计算值) |
|------|------|--------------|-----------|----------------------|
| ARC | 微偏修正（仅中间单灯偏移） | 3000 | 50% | 1500 |
| CORNER | 大偏急转（外灯亮或脱线升级） | 3200 | 90% | 2880 |
| SETTLE | 收尾减小超调（即将转正） | 2400 | 42% | 1008 |
| SEARCH | 脱线找线（全白搜索） | 2900 | 69% | 2001 |

**PWM Slew Rate Limiter**（防方向反转冲击）：当车轮需要从正转切换到反转时，不是直接跳变，而是经过三步渐变：

1. **快速制动**：正转 → 0，步进 650/ms（`REVERSE_BRAKE_STEP`）；
2. **缓慢加速反转**：0 → 反转目标，步进 320/ms（`REVERSE_ACCEL_STEP`）；
3. **同向调整**：其他情况步进 420/ms（`SLEW_STEP`）。

**非对称去抖滤波**（传感器层面）：检测到黑线（LOW）时立即更新为 0；检测到白地（HIGH）时需连续 3 次（`IRTRACK_RELEASE`）读数均为高才更新为 1。防止 IR 接收管释放慢导致的"粘滞低电平"误判。

**转向决策逻辑**：

| 传感器状态 | 误差值 | 决策 | 档位 |
|-----------|--------|------|------|
| 仅中间两灯在黑线上 | 0 | 直行 | — |
| 左内灯偏移 | −1 | 左弧线修正 | ARC |
| 右内灯偏移 | +1 | 右弧线修正 | ARC |
| 左外灯亮（无中间灯） | −3 | 左大偏转弯 | CORNER |
| 右外灯亮（无中间灯） | +3 | 右大偏转弯 | CORNER |
| 全白（脱线） | 维持上次 | 按上次方向搜索 | SEARCH |
| 全黑（交叉线） | 0 | 直行穿过 | — |

**脱线恢复**：直行模式下全白时先给予 2 ms 宽限期（`LOST_GRACE_MS`），超期后按 `last_turn` 方向开始旋转搜索；转弯模式下脱线持续 2 ms（`LOST_TO_CORNER_MS`）后升级为 CORNER 档加速找线。

**转弯稳定机制**：
- 转弯最短保持 7 ms（`TURN_MIN_HOLD_MS`），过滤瞬间回中；
- 回中需连续 6 ms（`CENTER_CONFIRM_MS`）中心双灯稳定才切回直行；
- 反向传感器确认需 5 ms（`OPPOSITE_CONFIRM_MS`），防止交叉线误判。

#### 3.1.2 障碍物检测与超车避让（FR-02, FR-03, FR-07）

**功能概述**：AGV 小车在循迹行驶过程中，通过 HC-SR04 超声波测距传感器实时检测前方障碍物距离，根据距离阈值分级响应（降速/停车/超车避让），超车机动委托通用状态机执行。

##### 3.1.2.1 超声波测距（FR-02）

1. HC-SR04 超声波测距传感器：触发引脚 PF11（推挽输出），回波引脚 PF12（EXTI 上升/下降沿中断）；
2. 触发方式：PF11 输出 >10 μs 高电平脉冲，HC-SR04 自动发射 8 个 40 kHz 方波；
3. 测距原理：回波高电平脉宽 = 超声波往返时间；距离计算：

```
distance_mm = echo_us × 340 / 2 / 1000 ≈ echo_us × 5 / 29
```

4. 计时方式：DWT CYCCNT 周期计数器（72 MHz），1 μs = 72 cycles；
5. 触发间隔：60 ms（`FA_ULTRASONIC_TRIGGER_MS`），避免前次回波干扰；
6. 最大回波超时：35,000 μs（`ULTRASONIC_MAX_ECHO_US`），对应约 6 m 量程上限；
7. 测距范围：2 cm ~ 400 cm（HC-SR04 物理极限），精度约 3 mm。

##### 3.1.2.2 超声避障超车（FR-03）

1. 距离 ≤ 30 cm（`FA_WARN_DIST` = 300 mm）时，循迹降速至 `FA_LINE_SLOW_SPEED` = 2100；
2. 距离 ≤ 15 cm（`FA_STOP_DIST` = 150 mm）时，停车 0.5 s（`FA_STOP_DELAY_MS`）后触发超车；
3. 超车顺序：**右超车 → 直行等待 2 s → 左超车 → 旋转找线 → 恢复循迹**；
4. 超车机动委托通用 `overtake.c` 状态机（详见 3.1.2.3）；
5. 左右超车参数独立配置（`fa_set_ovt1_config()` / `fa_set_ovt2_config()`），通过 `Overtake_SetConfig()` 注入，补偿物理不对称；
6. 旋转找线（FA_SEARCH）：超车完成后原地右旋寻找黑线，3 s 超时（`FA_SEARCH_TIMEOUT_MS`）则停车交由循迹脱线恢复处理。

##### 3.1.2.3 超车机动状态机（`overtake.c`）

通用 5 状态超车机动驱动，左右超车通过方向参数区分：

```
┌─────────────────────────────────────────────────────┐
│  左超车流程 (direction = +1):                         │
│  IDLE → STOP → ROTATE_LEFT(90°) → PASS → ROTATE_RIGHT(90°) → IDLE │
│                                                       │
│  右超车流程 (direction = -1):                         │
│  IDLE → STOP → ROTATE_RIGHT(90°) → PASS → ROTATE_LEFT(90°) → IDLE │
└─────────────────────────────────────────────────────┘
```

| 状态 | 动作 | 持续时间 | LED | 蜂鸣器 |
|------|------|---------|-----|--------|
| IDLE | 停车等待触发 | — | — | — |
| STOP | 停车等待 | `stop_delay_ms` | STOP(红快闪) | ON |
| ROTATE_1 | 原地旋转（方向取决于超车方向） | `rotate_ms` | ROTATE | OFF |
| PASS | 直行超越障碍物 | `pass_ms` | FORWARD(绿) | OFF |
| ROTATE_2 | 反向旋转回原朝向 | `rotate_ms` | ROTATE | OFF |

> **物理接线修正**：`do_rotate_left()` 内部调用 `pwm_car_rotate_right()`，`do_rotate_right()` 调用 `pwm_car_rotate_left()`——代码与物理旋转方向相反，已在代码中修正。

##### 3.1.2.4 综合循迹避障状态机（`follow_avoid.c`，FR-07）

6 状态优先级状态机，避障优先级高于循迹：

```
                ┌──────────┐
                │ FA_FOLLOW│◄─────────────────── 找到黑线 / 超时
                │ (循迹)   │
                └──┬───────┘
                   │ dist ≤ STOP_DIST
                   ▼
                ┌──────────┐
                │  FA_STOP │
                │ (停车0.5s)│
                └──┬───────┘
                   │ timeout
                   ▼
                ┌──────────┐    complete     ┌──────────┐
                │ FA_OVT_1 │───────────────►│  FA_WAIT │
                │ (右超车)  │               │ (直行2s) │
                └──────────┘               └──┬───────┘
                                               │ timeout
                                               ▼
                                          ┌──────────┐   complete + 找到线
                                          │ FA_OVT_2 │──────────────► FA_FOLLOW
                                          │ (左超车)  │
                                          └──┬───────┘
                                             │ complete + 未找到线
                                             ▼
                                          ┌──────────┐
                                          │FA_SEARCH │──找到线──► FA_FOLLOW
                                          │(旋转找线) │
                                          └──┬───────┘
                                             │ 超时3s
                                             ▼
                                          停车（交由循迹脱线恢复）
```

**关键设计决策**：

1. `Overtake_Tick()` 仅在 `FA_OVT_1` / `FA_OVT_2` 状态调用，避免循迹期间空跑超车状态机；
2. 超声测距每 60 ms 触发一次，距离值仅在非零时更新 `last_dist`，防止读 0（未就绪）时误触发；
3. 超车完成后先检查 `IRTracking_ReadAll() != 0x0F`（非全白=找到线），找到则直接恢复循迹，否则进入搜索；
4. FA_SEARCH 原地右旋（`pwm_car_rotate_left(FA_SEARCH_SPEED)`——物理接线反向，代码 left = 实际右旋）。

#### 3.1.3 K210 视觉识别与指令响应（FR-05, FR-06）

##### 3.1.3.1 通讯协议

**帧格式**：`$payload#`，其中 `$` 为帧起始符，`#` 为帧结束符，payload 为有效数据。

**STM32 接收（RXNE 中断逐字节解析）**：

```
状态机：IDLE → '$' → RECEIVING → 收集字符 → '#' → 完成
- '$'：清空缓冲区，开始接收
- '#'：NUL 终止缓冲区，置 msg_ready 标志
- 其他：存入缓冲区（溢出则丢弃整帧）
```

**K210 → STM32 指令集**：

| 帧内容 | 含义 | STM32 响应 |
|--------|------|-----------|
| `$L#` | LEFT 路牌 | 触发左超车机动 |
| `$R#` | RIGHT 路牌 | 触发右超车机动 |
| `$H#` | HORN | 蜂鸣器响 |
| `$W#` | SLOW | 降速行驶 (2100) |
| `$F#` | FAST | 恢复正常速度 (2300) |
| `$D#` | RED_LIGHT | 停车 |
| `$Y#` | YELLOW_LIGHT | 停车 |
| `$G#` | GREEN_LIGHT | 通行/恢复 |
| `$B#` | BACK_IN | 倒车 |
| `$S#` | STOP | 紧急停车 |
| `$e<value>#` | 视觉循迹误差 | value: −100~+100 (负=偏左, 正=偏右), 999=脱线 |
| `$a#` | ALIVE 心跳回复 | 确认通讯正常 |

**STM32 → K210**：

| 帧内容 | 含义 | 发送频率 |
|--------|------|---------|
| `$alive#` | 心跳 | 每 1 s |

**通讯超时处理**：若超过设定时间未收到 K210 消息，按上次误差方向旋转找线。

##### 3.1.3.2 视觉驾驶状态机（`vision_drive.c`，FR-05）

7 状态，路牌指令触发超车机动或驾驶行为：

```
                ┌──────────┐
                │  VD_IDLE │◄───── G/F 指令
                │ (正常前进)│
                └──┬───────┘
           L/R指令  │         S/D/Y指令         W指令        B指令
          ┌────────┴────────┐──────────┐──────────┐──────────┐
          ▼                  ▼          ▼          ▼          ▼
    ┌──────────┐     ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐
    │ VD_OVT_1 │     │VD_STOPPED│ │  VD_SLOW │ │VD_BACKING│
    │ (超车1)  │     │ (停车)   │ │ (慢速)   │ │ (倒车)   │
    └──┬───────┘     └──────────┘ └──────────┘ └──────────┘
       │ complete
       ▼
    ┌──────────┐
    │VD_FWD_WAIT│ (直行等待 1000ms)
    └──┬───────┘
       │ timeout
       ▼
    ┌──────────┐    complete
    │ VD_OVT_2 │──────────► VD_IDLE
    │ (超车2)  │
    └──────────┘
```

**视觉驾驶参数**：

| 参数 | 值 | 说明 |
|------|-----|------|
| `VD_FORWARD_SPEED` | 2300 | 正常前进速度 |
| `VD_SLOW_SPEED` | 2100 | 限速前进速度 |
| `VD_BACK_SPEED` | 2300 | 倒车速度 |
| `VD_FWD_WAIT_MS` | 1000 | 两次超车间直行时间 |

##### 3.1.3.3 K210 自学习分类器

- 模型：`mb-0.25.kmodel`（MobileNet 0.25，KPU 加速）；
- 9 类路牌：LEFT / RIGHT / HORN / SLOW / FAST / RED / YELLOW / GREEN / BACK；
- 发送策略：连续 `STABLE_FRAMES` 帧确认后发送指令，`REARM_FRAMES` 帧后允许重触发；
- K210 UART1：TX=IO8, RX=IO6, 115200 8N1。

#### 3.1.4 故障报警及处理（FR-08）

1. **RGB LED 灯**：左右各一组 RGB LED，左 (PG1-R / PE7-G / PG2-B)，右 (PE2-R / PE3-G / PE4-B)；
2. **LED 驱动**：8 参数 API `LED_Set(l_r, l_g, l_b, l_blink, r_r, r_g, r_b, r_blink)`，支持：
   - RGB 混色：r/g/b 强度 0~100%
   - 闪烁模式：0=稳态, 1=慢闪(1 Hz), 2=快闪(5 Hz)
   - 软件 PWM：100 Hz（`LED_PWM_PERIOD` = 100），通过 BSRR 原子操作写 GPIO
3. **预设灯光方案**：

| 预设 | 左灯 | 右灯 | 场景 |
|------|------|------|------|
| FORWARD | 绿(100) | 绿(100) | 正常行驶 |
| STOP | 红(100)快闪 | 红(100)快闪 | 停车/避障 |
| BACKWARD | 黄(100,80) | 黄(100,80) | 倒车 |
| TURN_LEFT | 绿(100) | 黄(100,80)慢闪 | 左转 |
| TURN_RIGHT | 黄(100,80)慢闪 | 绿(100) | 右转 |
| ROTATE | 红(100)慢闪 | 绿(100)慢闪 | 旋转 |

4. **蜂鸣器**：PG12，高电平有效，`Buzz_On()` / `Buzz_Off()` 直接 GPIO 写；
5. **按键**：KEY1(PG3) 开蜂鸣，KEY2(PG4) 关蜂鸣，20 ms 防抖（`Key_Tick` 1 kHz 采样）；
6. **自动报警**：超声波检测到障碍物时 STOP 状态自动触发红快闪+蜂鸣；超车期间 ROTATE/PASS 状态对应灯光+蜂鸣关闭；
7. **脱线报警**：循迹丢失黑线超过 3 s 时停车；
8. **通讯超时**：K210 通讯超时时自动切换为旋转找线模式。

#### 3.1.5 红外避障（FR-04）

1. 左发射 PE5 + 接收 PF9，右发射 PE6 + 接收 PF10；
2. 发射管 active-LOW：`GPIO_PIN_RESET` = ON，`GPIO_PIN_SET` = OFF；
3. 接收管 active-low：LOW = 检测到障碍物，`IRAvoid_ReadLeft/Right()` 返回 1 表示有障碍；
4. 非对称去抖滤波：
   - 左侧：`IRAVOID_L_RELEASE` = 1（基本即时释放）
   - 右侧：`IRAVOID_R_RELEASE` = 10（10 ms 连续清零才释放，因右侧接收管释放慢）
5. 可组合 `ir_avoid_drive.c`：仅左障碍→右超车，仅右障碍→左超车，双侧→左超车，无障碍→前进。

#### 3.1.6 红外遥控功能（FR-09）

1. PG11 接收红外遥控信号（NEC 协议），EXTI 下降沿中断 + DWT 精确计时解码；
2. NEC 协议时序：

| 信号 | 脉冲宽度 | 含义 |
|------|---------|------|
| 引导码 (Header) | 9 ms AGC + 4.5 ms 间隔 | 帧起始 |
| 重复码 (Repeat) | 9 ms AGC + 2.25 ms 间隔 | 长按重复 |
| 逻辑 0 | 562.5 μs 高 + 562.5 μs 低 | 数据位 0 |
| 逻辑 1 | 562.5 μs 高 + 1,687.5 μs 低 | 数据位 1 |

3. 帧格式：32 位 = 8 位地址 + 8 位地址反码 + 8 位命令 + 8 位命令反码，校验：`addr == ~addr_inv && cmd == ~cmd_inv`；
4. 容差：Header ±1500 μs，Repeat ±1000 μs，Bit ±400 μs；
5. 帧超时：15 ms（`NEC_FRAME_TIMEOUT_MS`），防止半帧残留；
6. 支持急停、前进、后退、左转、右转、旋转 90°、调速（步进 10，范围 600~3600）、蜂鸣、灯光等遥控指令；
7. 默认 PWM 速度 2100；
8. DWT CYCCNT 与超声波共享——`IRRemote_Init()` 检测计数器已启用则跳过重置。

#### 3.1.7 OLED 状态显示（FR-10）

1. SSD1306 128×32 OLED 通过 I2C1（PB6 SCL / PB7 SDA，地址 0x3C）连接；
2. 支持 3 种字体：7×10、11×18、16×26；
3. 实时显示循迹状态、超声波距离、超车阶段、K210 路牌识别结果等调试信息；
4. 刷新间隔可配置（如 `FA_DISPLAY_MS` = 80 ms），避免 I2C 阻塞影响控制周期；
5. ⚠️ `OLED_Puts()` 不会自动清除旧文本——需 `OLED_Clear()` + 重绘。

#### 3.1.8 电机驱动（FR-12）

1. **硬件**：4 个直流电机 + AT8236 H 桥驱动（L293D 兼容），TIM1 CH1-4 (PE9/PE11/PE13/PE14, remap) 驱动电机 1-2，TIM8 CH1-4 (PC6/PC7/PC8/PC9) 驱动电机 3-4；
2. **PWM 参数**：ARR = 3599，频率 = 72 MHz / 3600 = 20 kHz；
3. **电机布局**：Motor1/2 = 物理右侧（前右+后右），Motor3/4 = 物理左侧（前左+后左）；
4. **H 桥控制**：前进 IN1=PWM, IN2=0；后退 IN1=0, IN2=PWM；停止 IN1=IN2=0；制动 IN1=IN2=ARR(100%占空比)；
5. **逐电机修正**：`MOTORn_CORR` (100=无修正) + `MOTORn_REVERSE` (1=逻辑反转)；
6. **差速转弯**：`car_diff_turn(left, right)` 有符号差速驱动，正=前进/负=后退/0=停止，允许内侧轮负速度→自动原地旋转；
7. **能耗制动**：`car_brake()` 所有 8 路 CCR=3600(>ARR)→恒高→H桥 A=B=1→电机端子短接→快速制动，远快于自由滑行；
8. **⚠ 最低启动速度**：PWM speed 必须 ≥ 2100 才能克服静摩擦使车轮转动，所有 `*_SPEED` 参数不得低于 2100。

**电机修正参数**：

| 电机 | CORR | REVERSE | 物理位置 |
|------|------|---------|---------|
| Motor1 | 100 | 0 | 右前 |
| Motor2 | 100 | 0 | 右后 |
| Motor3 | 100 | 1 | 左前 |
| Motor4 | 100 | 1 | 左后 |

#### 3.1.9 编码器测速反馈（FR-11，开发中）

1. TIM2/3/4/5 编码器接口模式，四路正交编码器：

| 编码器 | 定时器 | 引脚 | REVERSE |
|--------|--------|------|---------|
| Encoder1 | TIM4 | PD12/PD13 | 1 |
| Encoder2 | TIM2 | PA15/PB3 | 1 |
| Encoder3 | TIM5 | PA0/PA1 | 0 |
| Encoder4 | TIM3 | PB4/PB5 (partial remap) | 0 |

2. 中点计数法：CNT 初始化为 0x7FFF (32767)，每次读取后重置；`delta = 0x7FFF - CNT`，正=前进，负=后退；
3. 电机参数：PPR=13，减速比=30，倍频=×2，每转=780 counts；
4. 速度计算：`RPM = speed_cpr × 60000 / 780`；
5. 提供 `Encoder_GetDelta/GetTotal/GetSpeed` 接口，`Encoder_Tick()` 由 SysTick 1 kHz 驱动。

#### 3.1.10 超声波测速（FR-13）

1. 基于超声波距离读数估算接近速度：`speed_cm_s = -(Δdistance_mm × 100000) / Δtime_us`；
2. EMA 滤波平滑：`speed_ema = (raw × 25 + ema × 75 + 50) / 100`（α=0.25）；
3. 最小采样间隔 `ULTRASONIC_SPEED_MIN_DT` = 1000 DWT cycles (~14 μs)，防止噪声；
4. 由 `test_ultrasonic.c` 调用。

### 3.3 非功能需求

1. **实时性（NFR-01）**：所有驱动均为非阻塞设计，ISR 仅做时间戳/GPIO 采样（<1 μs），重逻辑在 SysTick Tick（1 ms 周期）中执行，主 `while(1)` 循环为空；
2. **安全性（NFR-02）**：永不同时启用两个电机驱动任务（编译期注释约束 + 运行期单任务启用），避免控制冲突；电机 PWM < 2100 无法转动视为安全停车区间；
3. **可维护性（NFR-03）**：驱动/配置分离，所有可调参数集中在 `*_config.h` 中（共 16 个配置文件），用户调参无需修改驱动代码；
4. **可扩展性（NFR-04）**：新驱动只需创建 `USER/driver/inc/xxx.h` + `USER/driver/src/xxx.c` + `USER/config/xxx_config.h` 文件对，CMake `file(GLOB_RECURSE ...)` 自动发现，无需修改构建脚本；
5. **鲁棒性（NFR-05）**：
   - 非对称去抖滤波（触发即时、释放需 N 次连续清零），防止传感器抖动导致的误触发；
   - EMA 滤波平滑测距/测速噪声（α=0.25）；
   - PWM slew limiter 防止电机方向反转冲击；
   - 超车完成后必须停车（`enter_idle()` 调用 `pwm_car_stop()`），防止电机保持旋转命令继续转动；
   - USART2 帧解析溢出时丢弃整帧，防止缓冲区溢出。

## 7 已知约束与风险

| 编号 | 约束/风险 | 影响 | 缓解措施 |
|------|----------|------|---------|
| C-01 | 电机 PWM < 2100 无法克服静摩擦 | 低速区间不可用 | 所有 `*_SPEED` 参数 ≥ 2100 |
| C-02 | PA3 (USART2_RX) 物理损坏 | 原始串口不可用 | AFIO 重映射至 PD5/PD6 |
| C-03 | 左右转方向物理接线与代码假设相反 | 代码语义与物理行为不一致 | `MOTOR3/4_REVERSE=1` 逻辑反转 + overtake 旋转函数互换 |
| C-04 | PG11 与 PF12 共享 EXTI15_10_IRQn | 两个中断源需软件分发 | 自定义 `EXTI15_10_IRQHandler` 按引号分发 |
| C-05 | LRGB_R_Pin (PG1) CubeMX 重生成后标签丢失 | 编译可能出错 | main.h 中手动 `#define` |
| C-06 | TIM3 编码器实际接线 PB4/PB5，CubeMX 配为 PA6/PA7 | 编码器 4 不可用 | tim.c USER CODE 块做 partial remap |
| C-07 | 不可同时启用两个电机驱动任务 | 电机控制冲突 | 手动注释约束 + 文档说明 |
| C-08 | OLED `OLED_Puts()` 不自动清除旧文字 | 显示重叠/残影 | 必须先 `OLED_Clear()` 再重绘 |
| C-09 | CubeMX 重生成后 CMakeLists.txt 需手动修复 | 构建失败 | 重生成后检查首行 `#` 和 `include_directories` |
| C-10 | DWT CYCCNT 为超声波与红外遥控共享 | 计数器冲突 | `IRRemote_Init()` 检测已启用则跳过重置 |
